## 🐛 修正されたバグ

### **1️⃣ iPhone でプロフィール写真のアップロードができない問題**

#### 問題
- iPhone Safari で写真選択時にカメラが起動しない
- ファイル選択ダイアログが表示されない

#### 原因
- `accept` 属性が特定のMIMEタイプ（image/jpeg, image/png等）に限定されていた
- `capture` 属性がなく、カメラへのアクセスが制限されていた

#### 修正内容
```html
<!-- 修正前 -->
<input type="file" accept="image/jpeg,image/jpg,image/png,image/heic,image/heif,image/webp" />

<!-- 修正後 -->
<input type="file" accept="image/*" capture="environment" />
```

#### 効果
- ✅ iPhone Safari でカメラまたはフォトライブラリから画像選択可能
- ✅ すべての画像形式に対応（HEIC/HEIF含む）

### **2️⃣ フレンド申請の承認システムバグ**

#### 問題
- 申請を**送った側**にも承認ボタンが表示されていた
- 本来は申請を**受け取った側**のみが承認すべき

#### 原因
- `loadFriends()` で incoming/outgoing の取得条件が逆だった
- `incoming`: `friend_user_id = currentUser.id` ← **間違い**
- `outgoing`: `user_id = currentUser.id` ← **間違い**

#### データベース構造（正しい理解）
```sql
-- friends テーブル
user_id: リクエストを受け取る側（承認する人）
friend_user_id: リクエストを送る側（承認を待つ人）
```

#### 修正内容
```javascript
// 修正前（間違い）
const { data: incomingRequests } = await supabase
  .from('friends')
  .eq('friend_user_id', currentUser.id)  // ❌ 逆
  .eq('status', 'pending');

// 修正後（正しい）
const { data: incomingRequests } = await supabase
  .from('friends')
  .eq('user_id', currentUser.id)  // ✅ 正しい
  .eq('status', 'pending');
```

#### 効果
- ✅ 申請を**受け取った側**のみに承認ボタン表示
- ✅ 申請を**送った側**は「承認待ち」表示のみ

## ✨ 新機能: 個別宣言システム

### **機能概要**
相棒と**違うタスク**でも一緒に挑戦できるように、それぞれが自分の宣言を設定可能に。

#### 実装前の制限
- 挑戦リクエストを送る人の宣言のみ
- 相棒は同じ宣言を共有する必要があった
- 柔軟性に欠けていた

#### 実装後
- ✅ 送る側: `user_declaration`（自分の宣言）
- ✅ 相棒側: `buddy_declaration`（相棒の宣言）
- ✅ それぞれ異なるタスクでOK

---

### **データベース変更**

#### Migration SQL
```sql
-- challenge_requests テーブル
ALTER TABLE challenge_requests 
ADD COLUMN IF NOT EXISTS buddy_declaration TEXT CHECK (length(buddy_declaration) <= 200);

ALTER TABLE challenge_requests 
RENAME COLUMN declaration TO user_declaration;

-- serious_room_challenges テーブル
ALTER TABLE serious_room_challenges 
ADD COLUMN IF NOT EXISTS buddy_declaration TEXT CHECK (length(buddy_declaration) <= 200);

ALTER TABLE serious_room_challenges 
RENAME COLUMN declaration TO user_declaration;
```

**実行方法**:
1. Supabase SQL Editor を開く: https://supabase.com/dashboard/project/mthfqqqukuvueprdokiq/sql
2. `migration_add_buddy_declaration.sql` の内容を貼り付けて実行

---

### **UI/UX 変更**

#### 1. 相棒宣言モーダル追加
- 挑戦リクエストを承認する際、相棒が自分の宣言を入力
- 10文字以上必須
- 200文字まで入力可能

#### 2. 挑戦詳細画面の表示
```
┌─────────────────────────────────┐
│ あなたの宣言                    │
│ 💭 毎日30分のランニング          │
└─────────────────────────────────┘

┌─────────────────────────────────┐
│ 相棒の宣言                      │
│ 💭 毎朝6時起床                   │
└─────────────────────────────────┘
```

#### 3. フロー変更
```
【修正前】
1. ユーザーAが宣言入力 → リクエスト送信
2. ユーザーBが承認 → 挑戦開始
   → 両者とも同じ宣言を共有

【修正後】
1. ユーザーAが宣言入力（user_declaration）→ リクエスト送信
2. ユーザーBがリクエスト確認
3. ユーザーBが自分の宣言入力（buddy_declaration）→ 承認
4. 挑戦開始
   → それぞれ異なる宣言で挑戦可能
```
