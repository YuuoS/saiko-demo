## ✨ 新機能

### 1. フレンド承認システム 🤝

従来の「即座にフレンドになる」方式から、**2段階承認システム**に変更しました。

#### 主な機能
- **フレンドリクエスト送信**
  - 招待コードでリクエストを送信
  - 相手が承認するまで `pending` 状態
  
- **リクエスト管理UI**
  - 📩 **受信リクエスト**: 承認/拒否ボタン付き
  - ⏳ **送信済みリクエスト**: 相手の承認待ち表示
  - フレンドリストと承認待ちリストの明確な分離

- **双方向フレンド関係**
  - 承認時に自動で双方向の関係を作成
  - 片方がフレンドを削除しても、もう一方の関係は維持される

#### データベース変更
```sql
ALTER TABLE friends ADD COLUMN status TEXT DEFAULT 'pending';
UPDATE friends SET status = 'approved' WHERE status IS NULL OR status = '';
```

**migration file**: `database_friend_approval.sql`

#### スクリーンショット（想定）
- フレンド画面: 承認待ちリクエストセクション
- 承認/拒否ボタンのインタラクション

## 📊 データベーススキーマ更新

### friends テーブル
**追加カラム**:
- `status` (TEXT) - デフォルト値: 'pending'
  - `'pending'`: 承認待ち
  - `'approved'`: 承認済み

**既存データの移行**:
```sql
-- 既存のフレンド関係を全て 'approved' に設定
UPDATE friends SET status = 'approved' WHERE status IS NULL OR status = '';
```

## 🚀 デプロイ手順

### 1. データベースマイグレーション

Supabase SQL Editor で以下を実行:

```sql
-- database_friend_approval.sql の内容を実行
ALTER TABLE friends ADD COLUMN IF NOT EXISTS status TEXT DEFAULT 'pending';
UPDATE friends SET status = 'approved' WHERE status IS NULL OR status = '';
```

### 2. RLS ポリシーの確認

`docs/rls-setup.md` を参照し、`friends` テーブルのRLSポリシーが正しく設定されているか確認してください。

特に以下のポリシーが必要:
- ✅ ユーザーは自分の送信したリクエストを閲覧可能
- ✅ ユーザーは自分に送られたリクエストを閲覧可能
- ✅ ユーザーは自分に送られたリクエストを承認（UPDATE）可能
- ✅ ユーザーは自分の送信したリクエストを削除可能

### 3. ファイルのデプロイ

以下のファイルを本番環境にデプロイ:
- `index.html` (更新)
- `reset-password.html` (更新)
- `README.md` (更新)
- `docs/friend-approval-test-guide.md` (新規)
- `database_friend_approval.sql` (新規)

### 4. キャッシュクリア

- Service Worker のキャッシュをクリア
- ユーザーに強制リロード（Ctrl+Shift+R / Cmd+Shift+R）を推奨
